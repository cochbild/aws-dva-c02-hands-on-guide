Study Sheets and Quizzes — Implementation Plan

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use [ ] markers for tracking.

Goal: Static HTML study sheets and exam-style quizzes for DVA-C02, with topic-level weak-area tracking, a weak-topics quiz, and a 65-question practice exam.

Architecture: One shared engine (study/assets/quiz.js) holds pure logic (pick, score, stats) plus DOM rendering. Each set has a sheet.html, a thin quiz.html, and a questions.js data file loaded by a script tag. study/registry.js lists every set and its topics. Progress lives in localStorage.

Tech stack: Plain HTML, CSS, and browser JavaScript (ES2020, no modules, so file:// works). Tests and the data checker run on Node 22 with node:test and node:vm. No dependencies.

Spec: docs/superpowers/specs/2026-10-18-study-quizzes-design.html

Global Constraints

  • Single app page — this overrides any page path in the tasks below. Every page that reads or writes progress is study/index.html, with hash routes: #home (default), #quiz/<set-id>, #weak, #exam. There is no per-set quiz.html, no weak-topics.html, and no final-exam.html. index.html loads registry.js, every questions.js, and quiz.js, then calls StudyQuiz.mountApp(container), which routes on hashchange to mountHome, mountSetQuiz, mountWeakQuiz, or mountExam (a route whose mount function does not exist yet shows "Not available yet" and a home link). Study sheets (study/sets/<set-id>/sheet.html) do not use storage; their "Take the quiz" links go to ../../index.html#quiz/<set-id> and "Home" to ../../index.html. Result topic links go to sets/<set-id>/sheet.html#<topic-id>. The data checker does not require a quiz.html. Reason: Firefox scopes localStorage for file:// pages per file or folder; one page works in every browser.
  • No build step, no frameworks, no npm packages, no CDN, no web fonts. Pages work offline from file://.
  • No fetch() for data. Data loads with <script src>.
  • Every localStorage read and write is inside try/catch. Storage key: dva-study-history-v1.
  • No alert(), confirm(), or prompt(). Use in-page confirmation.
  • Light and dark themes through prefers-color-scheme.
  • Study sheet prose: ASD-STE100 by intent. Quiz stems: AWS exam style ("Which solution will meet these requirements?"). All questions original.
  • Accuracy over volume. Any fact a reviewer cannot confirm against AWS documentation is fixed or removed.
  • Topic weak threshold: accuracy below 0.8 over the most recent 5 answers for the topic.
  • Set quiz: 15 questions per attempt. Bank: 30 to 40 questions per set, at least 2 per topic, 6 to 15 topics per set, about 20 to 25 percent multiple response.
  • Exam: 65 questions, 130 minutes, domain weights 1: 0.32, 2: 0.26, 3: 0.24, 4: 0.18 (confirm against the official guide in Task 13).
  • Commit author: Dale C <dalecochran1968@gmail.com>. Work on feature/study-quizzes. Do not push.

Review Focus

  1. Storage not available (private window, blocked site data, file:// restrictions): every page renders and a quiz can be taken and scored; progress shows as "not tested". Test in Task 1.
  2. Special characters in content (<, &, ${...}, JSON snippets in stems): text displays literally, never as HTML. Render with textContent. Test in Task 4.
  3. Bank smaller than requested count (weak-topics pool of 3, a gap set with 12 questions): the picker returns all available, no duplicates, no hang. Test in Task 1.
  4. Submit with unanswered questions: the page lists the unanswered question numbers and asks for an in-page second click; unanswered counts as wrong. Test in Task 4.
  5. Exam timer while the tab sleeps or the laptop suspends: remaining time comes from the start timestamp, not from a tick counter; at zero the exam submits. Test in Task 14.

Phase 1 — Engine and Module 1

Task 1: Engine logic

Files: Create study/assets/quiz.js, tools/tests/quiz-engine.test.js.

Interfaces — Produces (on window.StudyQuiz in the browser, and module.exports when module exists):

  • shuffle(arr, rng = Math.random) -> new array
  • pickBalanced(questions, count, rng) -> Question[]: round-robin across topics (topics in random order, questions within a topic in random order), length min(count, questions.length), no duplicates.
  • isCorrect(question, selected: number[]) -> boolean: exact set match of correct option indexes.
  • scoreAttempt(questions, answers: {[qid]: number[]}) -> { correct, total, byTopic: {[topic]: {correct,total}}, byDomain: {[d]: {correct,total}}, results: [{question, selected, ok}] }. Missing answer = wrong.
  • topicStats(history, n = 5) -> {[topic]: {accuracy, count}}: uses the most recent n entries per topic by t.
  • weakTopics(stats, threshold = 0.8) -> string[]: accuracy below threshold, worst first.
  • pickWeak(allQuestions, history, count = 15, rng) -> Question[]: only weak-topic questions; order of preference: last answer wrong, never seen, last answer right.
  • pickExam(allQuestions, count = 65, weights, rng) -> Question[]: per-domain quota by largest remainder (floor of count*w, then +1 to the largest fractional parts until the sum is count); balanced by topic inside each domain; if a domain is short, fill from other domains.
  • loadHistory() -> Entry[], appendHistory(entries) -> boolean, resetHistory() -> boolean: return [] / false when storage throws or holds bad JSON.
  • historyEntries(scoreResult, setIdOf: (qid) => string, now) -> Entry[]

    • scoreAttempt: unanswered counts in total and not in correct; byTopic and byDomain sums.
    • topicStats: 7 entries for a topic, oldest 2 wrong, newest 5 right → accuracy 1, count 5.
    • weakTopics: 0.8 is not weak, 0.6 is weak, order worst first.

Task 2: Data checker

Files: Create tools/validate-study.js, tools/tests/validate-study.test.js, tools/tests/fixtures/.

Interfaces — Produces: validateStudy(studyDir) -> { errors: string[], stats: { sets, questions, byDomain } }, exported. CLI: node tools/validate-study.js [studyDir] (default study) prints errors and stats, exits 1 on any error.

Loads registry.js and every sets/*/questions.js in one vm context with a window object. Checks:

  1. Set IDs, topic IDs, and question IDs are unique (across all sets).
  2. Each bank's setId is in the registry; each registry set has a bank, a sheet.html, and a quiz.html.
  3. Each question's topic belongs to its set in the registry.
  4. Each registry topic has an element with id="<topic>" in the set's sheet.html.
  5. Each topic has at least 2 questions.
  6. domain is 1, 2, 3, or 4.
  7. 4 to 6 options; at least 1 correct; every option has non-empty text and why; explanation non-empty.
  8. More than one correct → stem contains "(Choose two.)" or "(Choose three.)" matching the count. Exactly one correct → stem has no "(Choose".
