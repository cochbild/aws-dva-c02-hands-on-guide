Template anatomy

Sections

SectionPurpose
AWSTemplateFormatVersion, DescriptionFormat version and a text description (maximum 1,024 bytes).
MetadataExtra information about the template. CloudFormation does not change or mask it.
ParametersInput values at stack create or update.
RulesValidate a parameter or a combination of parameters.
MappingsLookup tables. Read them with Fn::FindInMap.
ConditionsDecide if a resource or output is created, or which property value to use.
TransformMacros. AWS::Serverless-2016-10-31 (SAM) and AWS::Include.
ResourcesThe only required section. Each resource has a logical ID, a type, and properties.
OutputsValues that the stack returns. Can be exported to other stacks.

Parameters

  • Basic types: String, Number, List<Number>, CommaDelimitedList.
  • AWS-specific types make the user pick an existing value in the account and Region. Examples: AWS::EC2::VPC::Id, AWS::EC2::KeyPair::KeyName, List<AWS::EC2::Subnet::Id>. The console shows a list of existing values.
  • Systems Manager parameter types: AWS::SSM::Parameter::Value<String> or AWS::SSM::Parameter::Value<AWS::EC2::Image::Id>. The user gives a Parameter Store key. CloudFormation reads the latest value at each create or update.
  • CloudFormation does not support a SecureString Parameter Store type as a template parameter type. Use a dynamic reference for secrets.
  • Constraints: AllowedValues, AllowedPattern, MinLength, MaxLength, MinValue, MaxValue, ConstraintDescription.
  • NoEcho: true masks the value as asterisks in describe calls and stack events. It does not mask values in the Metadata section, the Outputs section, or a resource Metadata attribute.

Pseudo parameters

Use them with Ref or Fn::Sub. You do not declare them: AWS::AccountId, AWS::Region, AWS::StackName, AWS::StackId, AWS::Partition, AWS::URLSuffix, AWS::NotificationARNs, AWS::NoValue.

Capabilities

  • A template with IAM resources needs CAPABILITY_IAM or CAPABILITY_NAMED_IAM. Without one, CloudFormation returns InsufficientCapabilities.
  • IAM resources with custom names (for example RoleName) need CAPABILITY_NAMED_IAM.
  • create-stack or update-stack directly from a template with a macro (SAM, AWS::Include) needs CAPABILITY_AUTO_EXPAND. Change sets do not need it, so aws cloudformation deploy and sam deploy need it only for a template with macros and nested stacks.

Numbers to memorize

QuotaValue
Resources in a template500
Parameters, outputs, mappings in a template200 each
Template body in a request51,200 bytes
Template body in an S3 object1 MB
Parameter value4,096 bytes

Exam signals

  • "Users must choose an existing VPC, catch typos at create time" → AWS-specific parameter type AWS::EC2::VPC::Id.
  • "Always use the latest AMI in every Region, no template edits" → AWS::SSM::Parameter::Value<AWS::EC2::Image::Id> with a public parameter.
  • "Password parameter shows in an output" → NoEcho does not mask Outputs.
  • "InsufficientCapabilities, the role has a fixed name" → CAPABILITY_NAMED_IAM.

Dynamic references

PatternSourceNotes
{{resolve:ssm:name:version}}Parameter Store String or StringListVersion is optional. Without it, CloudFormation uses the latest version at create or update.
{{resolve:ssm-secure:name:version}}Parameter Store SecureStringWorks only for a short list of properties, for example RDS MasterUserPassword and IAM user LoginProfile Password.
{{resolve:secretsmanager:secret-id:SecretString:json-key:version-stage:version-id}}Secrets ManagerWorks in all resource properties. Default version is AWSCURRENT. Use the full ARN for a secret in another account.
  • CloudFormation does not store the resolved secure value. It stores only the reference text.
  • If you change the secret value, CloudFormation does not update the resource. It reads the value again only when it creates or updates that resource.
  • Secure dynamic references do not work in custom resources. Dynamic references do not work in EC2 UserData or in AWS::CloudFormation::Init metadata.
  • Maximum 60 dynamic references in a template.

Exam signals

  • "Environment variable needs the queue URL, the policy needs the queue ARN" → !Ref Queue and !GetAtt Queue.Arn.
  • "Database password must not be in the template and must rotate automatically" → Secrets Manager dynamic reference.
  • "Remove a property in dev, set it in prod" → Fn::If with AWS::NoValue.
  • "Secret changed, but the resource still has the old value" → update the resource in the stack.

References: Fn::Sub, Dynamic references, ssm-secure (supported properties), secretsmanager, SQS queue return values, SNS topic return values.

Exports, nested stacks, and StackSets

Comparison

ItemExport + Fn::ImportValueNested stacksStackSets
PurposeShare values between independent stacksReuse a template as a component of one parent stackDeploy one template to many accounts and Regions
ScopeSame account and same RegionInside one stack hierarchyMany accounts and Regions
HowOutputs with Export: Name. The consumer uses !ImportValue name.AWS::CloudFormation::Stack with TemplateURL (S3). Parent reads !GetAtt Child.Outputs.Name.A stack set in an administrator account creates stack instances in target accounts.

Export rules

  • Export names must be unique in each account and Region.
  • After another stack imports a value, you cannot delete the exporting stack. You also cannot change or remove that output. Remove all imports first.
  • The export Name and Fn::ImportValue cannot use Ref or GetAtt to a resource.
  • aws cloudformation list-imports shows the stacks that use an export.

Nested stack rules

  • The top stack is the root stack. Start updates from the root stack. CloudFormation updates only the nested stacks with changes.
  • Termination protection is set on the root stack only.

StackSets

  • Self-managed permissions: you create AWSCloudFormationStackSetAdministrationRole in the administrator account and AWSCloudFormationStackSetExecutionRole in each target account.
  • Service-managed permissions: use AWS Organizations. StackSets creates the roles. You can turn on automatic deployment to accounts that join an organizational unit later.
  • Operation options: maximum concurrent accounts, failure tolerance (for each Region), Region order, sequential or parallel Regions.
  • A template update goes to all stack instances. You cannot update the template for only some stacks.

Exam signals

  • "Many teams' stacks use the shared VPC, protect it from deletion while in use" → export and import.
  • "Update fails: export cannot be updated because it is in use" → remove the imports first.
  • "Same baseline in every account of the organization, also new accounts" → StackSets, service-managed, automatic deployment.
  • "Reuse a standard component in many templates" → nested stack.

References: Exports, Nested stacks, StackSets concepts, Self-managed roles.

Stack updates and rollback

Update behaviors

BehaviorEffect
No interruptionSame physical ID. The resource keeps working.
Some interruptionSame physical ID. The resource can stop for a short time (for example, an EC2 instance restart).
ReplacementCloudFormation creates a new resource with a new physical ID, moves references, then deletes the old resource.
  • Each resource property page in the template reference shows its update behavior.
  • If you set a custom name (for example TableName or FunctionName), updates that need replacement fail. Change the name to replace the resource.

Change sets

  • A change set shows what CloudFormation will add, modify, or remove, and if it will replace a resource. Creating it does not change the stack.
  • A change set does not guarantee that the update succeeds.
  • After you run one change set, CloudFormation deletes the other change sets of that stack.

Protection

FeatureProtects againstFacts
Stack policyUpdates to listed resourcesAfter you set it, all resources are protected by default. Add explicit Allow statements. Actions: Update:Modify, Update:Replace, Update:Delete, Update:*. Principal must be *. You cannot delete it, only change it. Use a temporary override policy during one update.
Termination protectionDeletion of the stackOff by default. Set on the root stack only.
DeletionPolicyLoss of one resource when it is deletedSee the resource attributes topic.

Rollback and failures

  • By default, a failed create or update rolls back. For create, OnFailure can be ROLLBACK (default), DO_NOTHING, or DELETE. Disable rollback to keep resources for inspection.
  • Rollback triggers: CloudFormation watches up to 5 CloudWatch alarms during the operation and for a monitoring time of 0 to 180 minutes. An alarm in ALARM state rolls back the operation.
  • UPDATE_ROLLBACK_FAILED: fix the cause (for example, recreate a resource that someone deleted outside CloudFormation). Then run ContinueUpdateRollback. You can skip resources with ResourcesToSkip.
  • DELETE_FAILED (for example, a bucket with objects): delete again with RetainResources for that resource.
  • To find the cause, read the stack events. Find the first failed event and its status reason. Later events are often rollback noise.
  • CloudFormation does not see a change to only DeletionPolicy, UpdatePolicy, conditions, or outputs as an update. Change a resource Metadata attribute to force one.

Drift detection

  • Drift detection compares the actual resource configuration with the template and parameter values. It does not change resources.
  • Resource status: IN_SYNC, MODIFIED, DELETED, NOT_CHECKED (type not supported).
  • It checks only properties that you set explicitly, not default values. It does not check nested stacks. Run it on each nested stack.

Exam signals

  • "See if the update replaces the database before you apply it" → change set.
  • "Allow all updates except replacement of the database" → stack policy with a Deny on Update:Replace for that logical ID.
  • "Someone changed the security group in the console, find what differs from the template" → drift detection.
  • "Stack is in UPDATE_ROLLBACK_FAILED" → fix the resource, then continue update rollback.

References: Update behaviors, Change sets, Stack policies, Termination protection, Rollback triggers (0–180 minutes, 5 alarms), Troubleshooting, Drift detection.

Resource attributes and helper scripts

DeletionPolicy and UpdateReplacePolicy

AttributeApplies whenValues
DeletionPolicyThe stack is deleted, or you remove the resource from the templateDelete (default), Retain, Snapshot
UpdateReplacePolicyAn update replaces the resource (the old physical resource)Delete (default), Retain, Snapshot
  • DeletionPolicy default exception: AWS::RDS::DBCluster, and AWS::RDS::DBInstance without DBClusterIdentifier, default to Snapshot. UpdateReplacePolicy has no such exception: its default is always Delete.
  • Snapshot works for EBS volumes, RDS instances and clusters, ElastiCache clusters and replication groups, Neptune clusters, and Redshift clusters. DeletionPolicy: Snapshot also works for DocumentDB clusters, but the UpdateReplacePolicy list does not include DocumentDB. Snapshot does not work for S3 buckets or DynamoDB tables.
  • Retain works for every resource type. A retained resource still costs money.
  • CloudFormation cannot delete an S3 bucket that contains objects.

Other attributes

  • DependsOn: create this resource after another resource. Ref and GetAtt already make an implicit dependency.
  • Condition: create the resource only when the condition is true.
  • CreationPolicy: wait for success signals before CREATE_COMPLETE. Only for AWS::EC2::Instance, AWS::AutoScaling::AutoScalingGroup, AWS::CloudFormation::WaitCondition, and AWS::AppStream::Fleet.
  • ResourceSignal: Count (default 1) and Timeout in ISO 8601 format (default PT5M, maximum 12 hours). No signal in time: the resource fails and the stack rolls back.

Helper scripts (EC2)

ScriptJob
cfn-initReads AWS::CloudFormation::Init metadata. Installs packages, writes files, starts services.
cfn-signalSends a success or failure signal to a CreationPolicy or wait condition.
cfn-get-metadataReads metadata for a resource.
cfn-hupA daemon that finds metadata changes and runs hooks. Use it to apply configuration changes on a stack update without replacing the instance.

The scripts are installed in /opt/aws/bin on Amazon Linux AMIs. They do not run by default. Call them from UserData. Logs: /var/log/cfn-init.log and /var/log/cloud-init.log.

Custom resources

  • Type Custom::MyName or AWS::CloudFormation::CustomResource. The only required property is ServiceToken: a Lambda function ARN or an SNS topic ARN in the same Region.
  • CloudFormation sends Create, Update, and Delete requests. The request has a pre-signed S3 ResponseURL.
  • The provider must send SUCCESS or FAILED to the ResponseURL. If no response arrives, the stack waits for the timeout: 3,600 seconds (1 hour) by default. Set ServiceTimeout to fail sooner.
  • The cfn-response module is available only for inline code in the ZipFile property.
  • Return data (maximum 4,096 bytes). Read it with Fn::GetAtt.

Exam signals

  • "Keep the bucket and its data when the stack is deleted" → DeletionPolicy: Retain.
  • "Keep a backup of the old database when an update replaces it" → UpdateReplacePolicy: Snapshot.
  • "Stack is complete before the app on the instance is ready" → CreationPolicy with cfn-signal.
  • "Delete hangs for an hour on a custom resource" → the function did not send a response. Respond in every code path.
  • "Run logic that CloudFormation does not support" → Lambda-backed custom resource.

References: DeletionPolicy, UpdateReplacePolicy, CreationPolicy (PT5M default, 12 hours maximum), Helper scripts, Custom resources (3,600-second timeout), cfn-response module.

SAM templates

Key facts

  • Transform: AWS::Serverless-2016-10-31 makes a template a SAM template. CloudFormation expands SAM resources into normal CloudFormation resources.
  • Common resource types: AWS::Serverless::Function, Api (REST API), HttpApi, SimpleTable (DynamoDB table with a single-attribute primary key), LayerVersion, StateMachine, Application (nested application), Connector, GraphQLApi.
  • You can mix SAM resources and normal CloudFormation resources in one template.
  • The Events property of a function adds a trigger: Api, HttpApi, S3, SQS, SNS, DynamoDB, Kinesis, Schedule, EventBridgeRule, and others. An Api event with no API resource makes SAM create an implicit REST API.
  • SAM creates an execution role for each function unless you give a Role.

Globals

  • The Globals section sets shared properties for Function, Api, HttpApi, SimpleTable, StateMachine, and a few other types.
  • Override rules: a primitive value in the resource replaces the global value. Maps (for example environment variables) are merged, and the resource key wins. Lists are added: global items come first.
  • A resource cannot remove a property that Globals sets.

Permissions

  • Policies on a function accepts AWS managed policy names, inline policy documents, and policy templates.
  • Policy templates scope permissions to one resource. Examples: DynamoDBCrudPolicy, DynamoDBReadPolicy, S3ReadPolicy, S3CrudPolicy, SQSPollerPolicy, SQSSendMessagePolicy, SNSPublishMessagePolicy, LambdaInvokePolicy, SSMParameterReadPolicy, AWSSecretsManagerGetSecretValuePolicy, KMSDecryptPolicy, StepFunctionsExecutionPolicy, EventBridgePutEventsPolicy.
  • Syntax: - DynamoDBCrudPolicy: { TableName: !Ref Table }. A template with no placeholders still needs an empty object: - CloudWatchPutMetricPolicy: {}.
  • Connectors (AWS::Serverless::Connector, or the Connectors attribute on the source resource) create least-privilege policies between a source and a destination. Permissions are Read and Write.

Exam signals

  • "Least privilege to one DynamoDB table with the fewest template lines" → DynamoDBCrudPolicy policy template, or a connector.
  • "Ten functions use the same runtime, timeout, and variables" → Globals.
  • "Function must send messages to one queue, no hand-written IAM JSON" → SQSSendMessagePolicy or a connector with Write.

References: SAM resource types, Globals (override rules), Policy templates, Connectors.

SAM CLI workflow and local testing

Commands

CommandJob
sam initCreate a project from a template. Creates samconfig.toml.

sam buildBuild functions and layers into .aws-sam/build with a built template. --use-container builds in a Lambda-like container (needs Docker), for example for native dependencies.

  • "Integration tests call Lambda through the SDK, run them locally" → sam local start-lambda and the endpoint URL.
  • "See code changes in a dev stack in seconds" → sam sync --watch. Not for production.
  • "Native dependencies fail on Lambda after a build on Windows" → sam build --use-container.

References: sam build, sam local generate-event, sam local start-lambda (port 3001), sam sync, sam remote invoke.

SAM gradual deployments

Key facts

  • AutoPublishAlias: live publishes a new version when the code changes and points the alias live to it. Callers must use the alias.
  • DeploymentPreference makes SAM create the CodeDeploy application, the deployment group, and the CodeDeploy role for you. CodeDeploy shifts alias traffic.
  • Types: Canary10Percent5Minutes, Canary10Percent10Minutes, Canary10Percent15Minutes, Canary10Percent30Minutes, Linear10PercentEvery1Minute, Linear10PercentEvery2Minutes, Linear10PercentEvery3Minutes, Linear10PercentEvery10Minutes, AllAtOnce.
  • Canary: two steps. Linear: equal steps with equal time between them.
  • Alarms: CloudWatch alarms. If one goes off, CodeDeploy rolls back the deployment.
  • Hooks: PreTraffic runs before traffic shifts. PostTraffic runs after all traffic shifts. Both are optional.
  • A hook function must report its result to CodeDeploy with PutLifecycleEventHookExecutionStatus (Succeeded or Failed). Its role needs permission for that call.
  • CodeDeploy needs an earlier version to shift traffic from. For a new function, deploy first with AutoPublishAlias, then add DeploymentPreference.

Exam signals

  • "10% for 5 minutes, then all, roll back on errors, least effort" → Canary10Percent5Minutes with Alarms.
  • "Run a smoke test before any user traffic reaches the new version" → PreTraffic hook.
  • "Hook ran, but the deployment waits and then fails" → the hook did not call PutLifecycleEventHookExecutionStatus.

References: SAM gradual deployments, PutLifecycleEventHookExecutionStatus. Related set: Module 1 (Lambda versions and aliases).

AWS CDK concepts

Key facts

  • A CDK app contains stacks. A stack contains constructs. Each CDK stack becomes one CloudFormation stack.
  • You write the app in a programming language (TypeScript, JavaScript, Python, Java, C#, Go).

Construct levels

LevelWhat it isExample
L1One CloudFormation resource, no defaults. Name starts with Cfn.CfnBucket
L2One resource with safe defaults and helper methods (for example grant methods).s3.Bucket
L3 (patterns)Many resources for one common architecture.ApplicationLoadBalancedFargateService

CLI

CommandJob
cdk bootstrapDeploys the CDKToolkit stack: an S3 bucket for assets, an ECR repository for images, and IAM roles for deployment. Do it one time for each account and Region (environment).
cdk synthMakes the cloud assembly in cdk.out: a CloudFormation template for each stack and the assets.
cdk diffCompares the app with the deployed stack.
cdk deployDeploys through a CloudFormation change set by default. --hotswap updates supported resources (for example Lambda code) through service APIs. Development only: it causes drift.
cdk watchDeploys when files change. Uses hotswap by default.
  • Without bootstrap, only stacks with no assets and a template under 51,200 bytes deploy.
  • Grants add a least-privilege IAM policy to the function role. You do not write the policy JSON. Current form: table.grants.readData(fn) (the grants property on L2 constructs). Older study material shows table.grantReadData(fn). These methods still work, but the API reference marks them discouraged.
  • RemovalPolicy maps to DeletionPolicy. For stateful resources (S3 buckets, DynamoDB tables) the CDK default is RETAIN. This is the opposite of the CloudFormation default.
  • To delete a bucket with objects on cdk destroy, set removalPolicy: DESTROY and autoDeleteObjects: true.

Exam signals

  • "First cdk deploy in a new account fails, assets cannot upload" → cdk bootstrap.
  • "cdk destroy finished, but the bucket and table still exist" → default RemovalPolicy.RETAIN.
  • "Give a function read access to a table with the least code" → a grant method.

References: Constructs, Bootstrapping, cdk deploy (hotswap, 51,200 bytes), Grants, Table API (grants.readData), Removal policies. Related set: Module 8 (CI/CD).

One template, many environments

Template techniques

  • Add an environment parameter (for example EnvType with AllowedValues: [dev, prod]).
  • Mappings keyed by environment or Region give values such as instance size. Mapping keys and values are literals. You cannot use parameters or functions inside Mappings.
  • Conditions use Fn::Equals on parameters. Attach Condition to a resource or output. Use Fn::If for property values.
  • Conditions can use parameters, pseudo parameters, mappings, and other conditions. They cannot use resources or resource attributes.
  • Use one stack for each environment, from the same template. Add AWS::Region or the stack name to custom resource names so that names do not collide.

SAM configuration file

  • samconfig.toml (default) or samconfig.yaml stores CLI options as [environment.command.parameters].
  • The default environment is default. Example: [prod.deploy.parameters] with stack_name and parameter_overrides.
  • Deploy to staging: sam deploy --config-env staging. Command-line values override the file.

CodePipeline CloudFormation action

ActionModeEffect
CHANGE_SET_REPLACECreate the change set (replace it if it exists). Does not change the stack.
CHANGE_SET_EXECUTERun the change set.
CREATE_UPDATECreate or update the stack at once.
REPLACE_ON_FAILUREDelete and recreate a stack in a failed state. For testing only.
DELETE_ONLYDelete the stack.
  • Common pattern: CHANGE_SET_REPLACE, then a manual approval action, then CHANGE_SET_EXECUTE.
  • TemplateConfiguration is a file with parameter values and a stack policy, for example one file for each stage. ParameterOverrides are for values known only at run time.

CloudFormation service role

  • Pass a service role (RoleARN) when you create the stack. CloudFormation then uses that role for all operations on the stack.
  • Users then need permission for CloudFormation and iam:PassRole for the role. They do not need permission to create the resources directly.

Exam signals

  • "Deploy the same SAM template to staging with other values" → sam deploy --config-env staging.
  • "Prod gets an extra alarm, dev does not" → a condition on the alarm resource.
  • "Review the changes before production, then apply" → CHANGE_SET_REPLACE, manual approval, CHANGE_SET_EXECUTE.
  • "Developers deploy stacks but must not create resources directly" → CloudFormation service role.

References: Conditions, Mappings, SAM configuration file, CodePipeline CloudFormation action, CreateStack (RoleARN).

Packaging and project layout

Packaging

  • aws cloudformation package --s3-bucket ... (or the same job with sam package) uploads local paths (for example CodeUri, Lambda Code, nested stack TemplateURL) to S3. A folder becomes a .zip file. It writes a new template with the S3 locations.
  • aws cloudformation deploy creates a change set and runs it. With --no-execute-changeset, it stops after it creates the change set.
  • A template larger than 51,200 bytes must come from S3. Use deploy --s3-bucket.
  • sam deploy does the upload for you. resolve_s3 = true makes SAM create a managed bucket.
  • Container image functions: PackageType: Image. The image is in Amazon ECR (ImageUri). sam build builds the image from the Dockerfile in the function Metadata.

Project layout

  • template.yaml and samconfig.toml at the project root.
  • One folder for each function (its CodeUri), with its own dependency file (requirements.txt, package.json). Each package stays small.
  • Shared code goes in a layer (AWS::Serverless::LayerVersion with ContentUri). Functions list it in Layers.
  • Test events go in an events/ folder. Tests go in a tests/ folder.
  • Do not edit files in .aws-sam/build. sam build overwrites them.

Exam signals

  • "Template points to a local folder, create-stack fails" → aws cloudformation package, then deploy the output template.
  • "Template body is too large" → upload the template to S3.
  • "Five functions share a helper library" → a layer, and one folder for each function.

References: aws cloudformation package, aws cloudformation deploy, sam build output.
