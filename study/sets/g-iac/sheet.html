Template anatomy

Remember

  • Resources is the only required section of a CloudFormation template.
  • A logical ID is the name of a resource in the template. Example: OrdersTable.
  • A physical ID is the real name or ID that AWS gives the resource. Example: prod-OrdersTable-1A2B3C.
  • The Rules section validates parameters before CloudFormation creates or updates any resource.
  • A false Rules assertion stops the operation and shows the AssertDescription text.
  • The Mappings section holds lookup tables. Read them with Fn::FindInMap.
  • The Conditions section decides if a resource or output is created, or which property value to use.
  • The Transform section names macros that rewrite the template before CloudFormation creates resources.
  • The transform AWS::Serverless-2016-10-31 (SAM) expands SAM resources into full CloudFormation resources.
  • The transform AWS::Include inserts a template snippet that is stored in S3.
  • An Outputs value can be exported to other stacks.
  • CloudFormation does not mask the Metadata section. Do not put secrets in Metadata.
  • An AWS-specific parameter type accepts only a value that exists in the account and Region. Example: AWS::EC2::VPC::Id.
  • An SSM parameter type takes a Parameter Store key and reads the latest value at each create or update.
  • Use an SSM parameter type for a value that changes outside the template, such as the newest AMI ID.
  • CloudFormation does not support a SecureString parameter type. Use a dynamic reference for secrets.
  • Parameter constraints are AllowedValues, AllowedPattern, MinLength, MaxLength, MinValue, and MaxValue.
  • ConstraintDescription is the error text that the user sees when a value breaks a constraint.
  • NoEcho: true masks a parameter value as asterisks in describe calls and stack events.
  • NoEcho does not mask values in Metadata, in Outputs, or in a resource Metadata attribute.
  • Pseudo parameters, such as AWS::AccountId and AWS::Region, let one template work in any account and Region.
  • When Fn::If returns AWS::NoValue, CloudFormation removes that property from the resource.
  • AWS::Partition is aws, aws-cn in China, or aws-us-gov in GovCloud. Use it to build ARNs.
  • A template with IAM resources needs CAPABILITY_IAM or CAPABILITY_NAMED_IAM, or it fails with InsufficientCapabilities.
  • IAM resources with custom names (for example RoleName) need CAPABILITY_NAMED_IAM. CAPABILITY_IAM is not enough.
  • create-stack or update-stack on a template with macros needs CAPABILITY_AUTO_EXPAND.
  • A change set does not use CAPABILITY_AUTO_EXPAND, because you can review the processed template.
  • sam deploy still needs CAPABILITY_AUTO_EXPAND for a nested application (AWS::Serverless::Application).
  • A template has a limit of 500 resources.
  • A template has a limit of 200 parameters, 200 outputs, and 200 mappings.
  • A template body in a request has a limit of 51,200 bytes. A template in S3 has a limit of 1 MB.
  • A parameter value has a limit of 4,096 bytes. A template Description has a limit of 1,024 bytes.

Exam signals

  • "Users must choose an existing VPC, catch typos at create time" → AWS-specific parameter type AWS::EC2::VPC::Id, because CloudFormation checks that the VPC exists before it creates resources.
  • "Always use the latest AMI in every Region, no template edits" → AWS::SSM::Parameter::Value<AWS::EC2::Image::Id> with a public parameter. AWS updates the public parameter in each Region when it releases a new AMI, and CloudFormation reads it at each create or update.
  • "Password parameter shows in an output" → NoEcho does not mask Outputs.
  • "InsufficientCapabilities, the role has a fixed name" → CAPABILITY_NAMED_IAM, because CAPABILITY_IAM does not cover IAM resources with custom names.

Parameters

  • Basic types: String, Number, List<Number>, CommaDelimitedList.
  • AWS-specific types make the user pick an existing value in the account and Region. Examples: AWS::EC2::VPC::Id, AWS::EC2::KeyPair::KeyName, List<AWS::EC2::Subnet::Id>.
  • For an AWS-specific type, the console shows a list of existing values. A value that does not exist in the account and Region fails validation, so a typo does not reach resource creation.
  • Systems Manager parameter types: AWS::SSM::Parameter::Value<String> or AWS::SSM::Parameter::Value<AWS::EC2::Image::Id>. The user gives a Parameter Store key (a name, for example /aws/service/ami-amazon-linux-latest/amzn2-ami-hvm-x86_64-gp2), not the value.
  • For a Systems Manager parameter type, CloudFormation reads the latest value of that key at each create or update. Use this type for a value that changes outside the template, such as the newest AMI ID.
  • CloudFormation does not support a SecureString Parameter Store type as a template parameter type. Use a dynamic reference for secrets (see the next topic).
  • Constraints: AllowedValues, AllowedPattern (a regular expression), MinLength, MaxLength, MinValue, MaxValue. CloudFormation rejects a value that breaks a constraint. ConstraintDescription is the error text that the user then sees, for example "must contain only letters and numbers".
  • NoEcho: true masks the value as asterisks in describe calls and stack events. It does not mask values in the Metadata section, the Outputs section, or a resource Metadata attribute.

Pseudo parameters

Pseudo parameters are built-in values that CloudFormation supplies. You do not declare them. Use them with Ref or Fn::Sub so that one template works in any account and Region without hard-coded values: AWS::AccountId, AWS::Region, AWS::StackName, AWS::StackId, AWS::Partition, AWS::URLSuffix, AWS::NotificationARNs, AWS::NoValue.

  • AWS::NoValue: when Fn::If returns it, CloudFormation removes that property from the resource, as if you did not write it.
  • AWS::Partition: the partition segment of an ARN (arn:aws:...). It is aws in standard Regions, aws-cn in China, and aws-us-gov in GovCloud. Use it to build ARNs that work in every partition.
  • AWS::URLSuffix: the domain suffix, usually amazonaws.com.

Capabilities

  • A capability is an explicit acknowledgment that you pass with the create or update call (--capabilities). It confirms that you know the template can do something sensitive, such as change IAM permissions in the account.
  • A template with IAM resources needs CAPABILITY_IAM or CAPABILITY_NAMED_IAM. Without one, CloudFormation returns InsufficientCapabilities.
  • IAM resources with custom names (for example RoleName) need CAPABILITY_NAMED_IAM. CAPABILITY_IAM is not enough for them.
  • A macro (SAM, AWS::Include) changes the template while CloudFormation processes it. When you call create-stack or update-stack directly on such a template, pass CAPABILITY_AUTO_EXPAND to accept those changes without review.
  • A change set does not use CAPABILITY_AUTO_EXPAND, because you can review the processed template before you run it. aws cloudformation deploy and sam deploy use change sets. They still need it for a template that has macros and nested stacks, for example a SAM template with a nested application (AWS::Serverless::Application).

Intrinsic functions and dynamic references

Remember

  • Ref returns the value of a parameter, or the default identifier of a resource.
  • Fn::GetAtt returns a named attribute of a resource, for example Arn.
  • Fn::Sub puts values into a string. Example: !Sub 'arn:aws:s3:::${Bucket}/*'.
  • In Fn::Sub, ${Param} works like Ref and ${Res.Attr} works like Fn::GetAtt.
  • In Fn::Sub, ${!Literal} writes the literal text ${Literal}.
  • Fn::Join joins a list, Fn::Split splits a string, and Fn::Select picks one item by index.
  • Fn::ImportValue reads an export from another stack.
  • Fn::Base64 encodes a string in Base64, the format that EC2 UserData requires.
  • Fn::GetAZs lists the Availability Zones of a Region.
  • Fn::Equals, Fn::And, Fn::Or, and Fn::Not define conditions in the Conditions section.
  • Fn::If returns one of two values, based on a condition.
  • Ref on an SQS queue returns the queue URL, not the ARN.
  • Ref on an SNS topic returns the topic ARN.
  • Ref on an S3 bucket, Lambda function, DynamoDB table, or IAM role returns its name.
  • An IAM policy Resource needs an ARN. Use Fn::GetAtt with Arn for most resource types.
  • A dynamic reference ({{resolve:...}}) reads a value from Parameter Store or Secrets Manager at create or update.
  • {{resolve:ssm:...}} reads a Parameter Store String or StringList. Without a version, it reads the latest version.
  • {{resolve:ssm-secure:...}} works only for a short list of properties, for example RDS MasterUserPassword.
  • {{resolve:secretsmanager:...}} works in all resource properties. The default version is AWSCURRENT.
  • For a secret in another account, use the full ARN in the Secrets Manager dynamic reference.
  • CloudFormation does not store a resolved secure value. CloudFormation stores only the reference text.
  • A changed secret value does not update the resource. CloudFormation reads the value only when it creates or updates that resource.
  • Secure dynamic references do not work in custom resources.
  • Dynamic references do not work in EC2 UserData or in AWS::CloudFormation::Init metadata.
  • A template has a limit of 60 dynamic references.

Exam signals

  • "Environment variable needs the queue URL, the policy needs the queue ARN" → !Ref Queue and !GetAtt Queue.Arn.
  • "Database password must not be in the template and must rotate automatically" → Secrets Manager dynamic reference. The template holds only the reference, and Secrets Manager can rotate the secret, but Parameter Store has no automatic rotation.
  • "Remove a property in dev, set it in prod" → Fn::If with AWS::NoValue. In dev, Fn::If returns AWS::NoValue, and CloudFormation removes the property.
  • "Secret changed, but the resource still has the old value" → update the resource in the stack, because CloudFormation reads the secret only when it creates or updates that resource.

Dynamic references

A dynamic reference is a placeholder in a property value, in the form {{resolve:...}}. CloudFormation replaces it with the value stored in Parameter Store or Secrets Manager when it creates or updates the resource. The secret is then not in the template or in a parameter value.

PatternSourceNotes
{{resolve:ssm:name:version}}Parameter Store String or StringListVersion is optional. Without it, CloudFormation uses the latest version at create or update.
{{resolve:ssm-secure:name:version}}Parameter Store SecureStringWorks only for a short list of properties, for example RDS MasterUserPassword and IAM user LoginProfile Password. For a secret in any other property, use a Secrets Manager reference.
{{resolve:secretsmanager:secret-id:SecretString:json-key:version-stage:version-id}}Secrets ManagerWorks in all resource properties. Default version is AWSCURRENT. Use the full ARN for a secret in another account.
  • CloudFormation does not store the resolved secure value. It stores only the reference text.
  • If you change the secret value, CloudFormation does not update the resource. It reads the value again only when it creates or updates that resource.
  • Secure dynamic references do not work in custom resources.
  • Dynamic references do not work in EC2 UserData or in AWS::CloudFormation::Init metadata.
  • Maximum 60 dynamic references in a template.

Exports, nested stacks, and StackSets

Remember

  • An export shares a value between independent stacks in the same account and Region.
  • A nested stack reuses a template as a component of one parent stack.
  • A StackSet deploys one template to many accounts and Regions.
  • To export a value, add Export: Name to an output. The consumer stack uses !ImportValue name.
  • A nested stack is an AWS::CloudFormation::Stack resource with a TemplateURL in S3.
  • A parent stack reads a nested stack output with !GetAtt Child.Outputs.Name.
  • Use exports when separate teams own separate stacks and one stack needs a value from another.
  • Use nested stacks when a reusable component must be created, updated, and deleted with the parent.
  • Use StackSets when the same resources must exist in many accounts or Regions.
  • An export name must be unique in each account and Region.
  • You cannot delete an exporting stack while another stack imports its value.
  • You cannot change or remove an output while another stack imports it. Remove all imports first.
  • An export name cannot use Ref or GetAtt to a resource. Example: !Sub '${AWS::StackName}-VpcId'.
  • aws cloudformation list-imports shows the stacks that use an export.
  • Start nested stack updates from the root stack, not from a nested stack.
  • Termination protection is set on the root stack only. Nested stacks inherit termination protection from the root stack.
  • StackSets self-managed permissions need roles that you create. Use them for accounts outside your organization.
  • StackSets service-managed permissions use AWS Organizations, and StackSets creates the roles.
  • Only service-managed permissions can deploy automatically to accounts that join an OU later.
  • StackSets self-managed roles are AWSCloudFormationStackSetAdministrationRole and AWSCloudFormationStackSetExecutionRole.
  • StackSets failure tolerance is the number of stack failures allowed in each Region. One more failure stops the operation.
  • StackSets Region concurrency is sequential by default. Parallel sends the operation to all Regions at the same time.
  • A StackSet template update goes to all stack instances. You cannot update only some stacks.

Exam signals

  • "Many teams' stacks use the shared VPC, protect it from deletion while in use" → export and import, because CloudFormation blocks deletion of a stack while another stack imports its export.
  • "Update fails: export cannot be updated because it is in use" → remove the imports first.
  • "Same baseline in every account of the organization, also new accounts" → StackSets, service-managed, automatic deployment. Only service-managed permissions can deploy automatically to accounts that join the OU later.
  • "Reuse a standard component in many templates" → nested stack. Each template points to the one component template in S3 instead of a copy of its resources.

Export rules

  • Export names must be unique in each account and Region. A second stack that exports the same name fails to create or update.
  • After another stack imports a value, you cannot delete the exporting stack. You also cannot change or remove that output.
  • To delete the exporting stack or change the output, remove all imports first. The import rule stops a change that breaks the stacks that use the value.
  • The export Name and Fn::ImportValue cannot use Ref or GetAtt to a resource. Build the name from parameters or pseudo parameters instead, for example !Sub '${AWS::StackName}-VpcId'.
  • aws cloudformation list-imports shows the stacks that use an export.

Nested stack rules

  • The top stack is the root stack. Start updates from the root stack, not from a nested stack.
  • The parent manages each nested stack as one of its resources. CloudFormation updates only the nested stacks with changes.
  • Termination protection is set on the root stack only. Nested stacks inherit it from the root stack. You cannot set it on a nested stack directly.

StackSets

  • Self-managed permissions: you create AWSCloudFormationStackSetAdministrationRole in the administrator account and AWSCloudFormationStackSetExecutionRole in each target account. Choose it for accounts that are not in your AWS Organizations organization.
  • Service-managed permissions: use AWS Organizations. StackSets creates the roles. You can turn on automatic deployment to accounts that join an organizational unit (OU) later.
  • Operation options:
    • Maximum concurrent accounts: the number or percentage of accounts that get the operation at the same time.
    • Failure tolerance: the number or percentage of stack failures allowed in each Region. One more failure stops the operation.
    • Region order: the order in which the Regions get the operation.
    • Region concurrency: sequential (one Region at a time, the default) or parallel (all Regions at the same time).
  • A template update goes to all stack instances. You cannot update the template for only some stacks.

References: Exports, Nested stacks, StackSets concepts, Self-managed roles.

Stack updates and rollback

Remember

  • An update with no interruption keeps the physical ID, and the resource keeps working.
  • An update with some interruption keeps the physical ID, but the resource can stop for a short time.
  • A replacement creates a new resource with a new physical ID, then deletes the old resource.
  • A replaced database or table is a new, empty resource unless you restore the data.
  • Each resource property page in the template reference shows its update behavior.
  • A replacement of a resource with a custom name (for example TableName) fails. Change the name to replace the resource.
  • A change set shows the adds, modifications, removals, and replacements before you apply them.
  • Creating a change set does not change the stack.
  • A change set does not guarantee that the update succeeds. Some failures occur only at run time.
  • After you run one change set, CloudFormation deletes the other change sets of that stack.
  • A stack policy controls which update actions are allowed on which resources, for everyone who updates the stack.
  • A stack policy denies updates to all resources by default. Add explicit Allow statements.
  • In a stack policy, an explicit Deny wins over an Allow.
  • Stack policy actions are Update:Modify, Update:Replace, Update:Delete, and Update:*.
  • A stack policy Principal must be *.
  • You cannot delete a stack policy. You can only change it.
  • To change a protected resource one time, pass a temporary override stack policy with that update.
  • Termination protection is off by default. While termination protection is on, a delete request fails.
  • A failed create or update rolls back by default and deletes the resources that CloudFormation created.
  • For create, OnFailure is ROLLBACK (default), DO_NOTHING, or DELETE.
  • To keep the created resources for inspection, use DO_NOTHING or --disable-rollback.
  • Rollback triggers watch up to 5 CloudWatch alarms.
  • Rollback triggers keep watching for 0 to 180 minutes after all resources are deployed.
  • Use rollback triggers to undo a release that deploys correctly but makes the application fail.
  • UPDATE_ROLLBACK_FAILED means that the rollback itself failed. The stack cannot update in this state.
  • To recover from UPDATE_ROLLBACK_FAILED, fix the cause, then run ContinueUpdateRollback.
  • ContinueUpdateRollback can skip resources that cannot roll back with ResourcesToSkip.
  • To recover from DELETE_FAILED, delete the stack again and list the resource in RetainResources.
  • To find the cause of a failure, read the first failed stack event.
  • A change to only DeletionPolicy, UpdatePolicy, conditions, or outputs is not an update.
  • To force an update, change a resource Metadata attribute.
  • Drift detection compares the actual resource configuration with the template. Drift detection does not change resources.
  • Drift status values are IN_SYNC, MODIFIED, DELETED, and NOT_CHECKED.
  • Drift detection checks only properties that you set explicitly, not default values.
  • Drift detection does not check nested stacks. Run drift detection on each nested stack.

Exam signals

  • "See if the update replaces the database before you apply it" → change set. It shows a Replacement value for each changed resource and does not change the stack.
  • "Allow all updates except replacement of the database" → stack policy with an Allow on Update:* and a Deny on Update:Replace for that logical ID. The Deny wins for that one resource.
  • "Someone changed the security group in the console, find what differs from the template" → drift detection, because only drift detection reads changes made outside CloudFormation.
  • "Stack is in UPDATE_ROLLBACK_FAILED" → fix the resource, then continue update rollback. The stack cannot update until the rollback completes.

Some interruptionSame physical ID. The resource can stop for a short time (for example, an EC2 instance restart).
ReplacementCloudFormation usually creates a new resource with a new physical ID first. Then it points the resources that refer to it to the new resource, and deletes the old resource. A replaced database or table is a new, empty resource unless you restore the data.

  • If you set a custom name (for example TableName or FunctionName), updates that need replacement fail. CloudFormation creates the new resource before it deletes the old one, and the old resource still has that name. Change the name to replace the resource.

Change sets

  • A change set shows what CloudFormation will add, modify, or remove, and if it will replace a resource. Creating it does not change the stack.
  • A change set does not guarantee that the update succeeds. CloudFormation checks common causes when it creates the change set, but some failures occur only at run time, for example in custom resource code.
  • After you run one change set, CloudFormation deletes the other change sets of that stack, because they describe changes to the old stack state.

Rollback and failures

  • By default, a failed create or update rolls back: CloudFormation returns the stack to its last working state and deletes the resources that it created.
  • For create, OnFailure can be ROLLBACK (default), DO_NOTHING, or DELETE. DO_NOTHING (or --disable-rollback) keeps the created resources so that you can inspect them. DELETE deletes the whole stack.
  • Rollback triggers: CloudFormation watches up to 5 CloudWatch alarms during the operation. It also watches them for a monitoring time of 0 to 180 minutes after all resources are deployed.
  • For rollback triggers, an alarm in ALARM state rolls back the operation. Use them to undo a release that deploys correctly but makes the application fail.
  • UPDATE_ROLLBACK_FAILED means that the rollback itself failed. You cannot update the stack in this state.
  • To recover from UPDATE_ROLLBACK_FAILED, fix the cause (for example, recreate a resource that someone deleted outside CloudFormation). Then run ContinueUpdateRollback. You can skip resources that cannot roll back with ResourcesToSkip.
  • DELETE_FAILED (for example, CloudFormation cannot delete a bucket with objects): delete the stack again and list that resource in RetainResources. CloudFormation then deletes the stack and keeps that resource.
  • To find the cause, read the stack events. Find the first failed event and its status reason. Later failures are usually effects of the first failure or of the rollback.
  • CloudFormation does not see a change to only DeletionPolicy, UpdatePolicy, conditions, or outputs as an update. Change a resource Metadata attribute to force one.

Drift detection

  • Drift is a difference between the actual configuration of a resource and its definition in the template, for example after someone changes the resource in the console.
  • Drift detection compares the actual resource configuration with the template and parameter values. It does not change resources.
  • Resource status: IN_SYNC, MODIFIED, DELETED, NOT_CHECKED (type not supported).
  • It checks only properties that you set explicitly, not default values. A console change to a property that the template does not set is not reported.
  • Drift detection does not check nested stacks. Run it on each nested stack.

References: Update behaviors, Change sets, Stack policies, Termination protection, Rollback triggers (0–180 minutes, 5 alarms), Stack failure options (disable rollback), Troubleshooting, Drift detection.

Resource attributes and helper scripts

Remember

  • DeletionPolicy applies when the stack is deleted or the resource is removed from the template.
  • UpdateReplacePolicy applies to the old resource when an update replaces the resource.
  • DeletionPolicy does not apply to a replacement.
  • Both policies accept Delete (default), Retain, and Snapshot.
  • Retain keeps the resource and its data, but the stack no longer manages the resource.
  • Snapshot takes a backup snapshot and then deletes the resource.
  • Use Retain to keep using the resource. Use Snapshot when a backup is enough.
  • AWS::RDS::DBCluster, and AWS::RDS::DBInstance without DBClusterIdentifier, have a DeletionPolicy default of Snapshot.
  • The UpdateReplacePolicy default is always Delete, also for RDS.
  • Snapshot works for EBS, RDS, ElastiCache, Neptune, and Redshift. DeletionPolicy: Snapshot also works for DocumentDB.
  • Snapshot does not work for S3 buckets or DynamoDB tables.
  • Retain works for every resource type. A retained resource still costs money.
  • CloudFormation cannot delete an S3 bucket that contains objects.
  • DependsOn makes CloudFormation create a resource after another resource.
  • Ref and GetAtt make an implicit dependency. Use DependsOn only when no reference exists.
  • The Condition attribute creates the resource only when the condition is true.
  • CreationPolicy makes CloudFormation wait for success signals before CREATE_COMPLETE.
  • CreationPolicy works only for EC2 instances, Auto Scaling groups, wait conditions, and AppStream fleets.
  • ResourceSignal Count has a default of 1.
  • ResourceSignal Timeout has a default of PT5M and a maximum of 12 hours.
  • No signal before the timeout makes the resource fail, and the stack rolls back.
  • cfn-init reads AWS::CloudFormation::Init metadata, installs packages, writes files, and starts services.
  • cfn-signal sends a success or failure signal to a CreationPolicy or wait condition.
  • cfn-hup applies metadata changes on a stack update without replacing the instance.
  • cfn-get-metadata reads metadata for a resource.
  • The helper scripts do not run by default. Call the helper scripts from UserData.
  • The helper scripts are in /opt/aws/bin on Amazon Linux AMIs.
  • Helper script logs are /var/log/cfn-init.log and /var/log/cloud-init.log.
  • A custom resource runs your own code when the stack is created, updated, or deleted.
  • Use a custom resource for a task that CloudFormation does not support.
  • A custom resource needs only ServiceToken: a Lambda function ARN or SNS topic ARN in the same Region.
  • A custom resource provider must send SUCCESS or FAILED to the pre-signed S3 ResponseURL.
  • A custom resource with no response waits 3,600 seconds (1 hour) by default. Set ServiceTimeout to fail sooner.
  • The cfn-response module is available only for inline code in the ZipFile property.
  • Custom resource response data has a limit of 4,096 bytes. Other resources read it with Fn::GetAtt.

Exam signals

  • "Keep the bucket and its data when the stack is deleted" → DeletionPolicy: Retain.
  • "Keep a backup of the old database when an update replaces it" → UpdateReplacePolicy: Snapshot, because DeletionPolicy does not apply to a replacement.
  • "Stack is complete before the app on the instance is ready" → CreationPolicy with cfn-signal. CloudFormation waits for the signal that the UserData script sends after the app starts.
  • "Delete hangs for an hour on a custom resource" → the function did not send a response, so CloudFormation waits for the 1-hour timeout. Respond in every code path.
  • "Run logic that CloudFormation does not support" → Lambda-backed custom resource.

Explanation

DeletionPolicy and UpdateReplacePolicy

AttributeApplies whenValues
DeletionPolicyThe stack is deleted, or you remove the resource from the templateDelete (default), Retain, Snapshot
UpdateReplacePolicyAn update replaces the resource (the old physical resource)Delete (default), Retain, Snapshot

Retain keeps the resource and its data, but the stack no longer manages it. Snapshot takes a backup snapshot and then deletes the resource.

Choose Retain to keep using the resource. Choose Snapshot when a backup is enough and you do not want to pay for the running resource.

  • DeletionPolicy default exception: AWS::RDS::DBCluster, and AWS::RDS::DBInstance without DBClusterIdentifier, default to Snapshot.
  • UpdateReplacePolicy has no such exception: its default is always Delete.
  • An instance inside a cluster (for example an Aurora instance) has no snapshot default of its own, because the cluster stores the data and the cluster snapshot covers it.
  • Snapshot works for EBS volumes, RDS instances and clusters, ElastiCache clusters and replication groups, Neptune clusters, and Redshift clusters. DeletionPolicy: Snapshot also works for DocumentDB clusters, but the UpdateReplacePolicy list does not include DocumentDB. Snapshot does not work for S3 buckets or DynamoDB tables.
  • Retain works for every resource type. A retained resource still costs money.
  • CloudFormation cannot delete an S3 bucket that contains objects.

Other attributes

  • DependsOn: create this resource after another resource. CloudFormation creates resources in parallel when it can.
  • Ref and GetAtt already make an implicit dependency, so you need DependsOn only when the order matters but no reference exists.
  • DependsOn examples: an EC2 instance with a public IP address must wait for the VPC gateway attachment. A resource that uses a role must wait for a separate AWS::IAM::Policy on that role, or it fails with insufficient permissions.
  • Condition: create the resource only when the condition is true.
  • CreationPolicy: wait for success signals before CREATE_COMPLETE. Without it, CloudFormation marks an instance complete when EC2 creates it, not when the software on it is ready. Only for AWS::EC2::Instance, AWS::AutoScaling::AutoScalingGroup, AWS::CloudFormation::WaitCondition, and AWS::AppStream::Fleet.
  • ResourceSignal: Count (default 1) and Timeout in ISO 8601 format (default PT5M, maximum 12 hours). No signal in time: the resource fails and the stack rolls back.

Custom resources

  • A custom resource runs your own code when the stack is created, updated, or deleted. Use it for a task that CloudFormation does not support, for example to look up a value or to call a third-party API.
  • Type Custom::MyName or AWS::CloudFormation::CustomResource. The only required property is ServiceToken: a Lambda function ARN or an SNS topic ARN in the same Region. The code behind it is the provider.
  • CloudFormation sends Create, Update, and Delete requests. The request has a ResponseURL: a pre-signed S3 URL, which lets the provider upload its result without AWS credentials.
  • The provider must send SUCCESS or FAILED to the ResponseURL. If no response arrives, the stack waits for the timeout: 3,600 seconds (1 hour) by default. Set ServiceTimeout to fail sooner.
  • The cfn-response module (a helper that sends the response) is available only for inline code in the ZipFile property. For code in a .zip file in S3, write your own code to send the response.
  • The provider can return data in the response (maximum 4,096 bytes). Other resources read it with Fn::GetAtt.

  • A map in a resource, such as environment variables, is merged with Globals. The resource key wins.
  • A list in a resource is added to the Globals list. Global items come first.
  • A resource cannot remove a property that Globals sets.
  • The function Policies property accepts managed policy names, inline policy documents, and policy templates.

Explanation

Key facts

  • Transform: AWS::Serverless-2016-10-31 makes a template a SAM template. CloudFormation expands SAM resources into normal CloudFormation resources.
  • Common resource types: AWS::Serverless::Function, Api (API Gateway REST API), HttpApi (API Gateway HTTP API), SimpleTable (DynamoDB table with a single-attribute primary key), LayerVersion (Lambda layer), StateMachine (Step Functions), Application (nested application: another SAM application deployed as a nested stack), Connector (permissions, see below), GraphQLApi (AppSync).
  • You can mix SAM resources and normal CloudFormation resources in one template.
  • The Events property of a function adds a trigger: Api, HttpApi, S3, SQS, SNS, DynamoDB, Kinesis, Schedule, EventBridgeRule, and others. SAM creates the trigger and the permissions that the trigger needs.
  • An Api event that does not point to an API resource makes SAM create a REST API for you (an implicit API).
  • SAM creates an execution role for each function unless you give a Role. The role gets the permissions in the function Policies property.

Globals

  • The Globals section sets shared properties for Function, Api, HttpApi, SimpleTable, StateMachine, and a few other types.
  • Override rules: a primitive value (a single value such as a string or number, for example Timeout) in the resource replaces the global value.
  • Maps (key-value sets, for example environment variables) are merged, and the resource key wins. Lists are added: global items come first.
  • A resource cannot remove a property that Globals sets. If one function must not have a property, do not put that property in Globals. Set it on each function that needs it.

Permissions

  • Policies on a function accepts AWS managed policy names, inline policy documents, and policy templates.
  • A policy template is a predefined IAM policy with placeholders. You give the resource name, and SAM writes a policy that allows only the needed actions on that one resource. You get least privilege without IAM JSON.
  • Policy template examples: DynamoDBCrudPolicy, DynamoDBReadPolicy, S3ReadPolicy, S3CrudPolicy, SQSPollerPolicy, SQSSendMessagePolicy, SNSPublishMessagePolicy, LambdaInvokePolicy, SSMParameterReadPolicy, AWSSecretsManagerGetSecretValuePolicy, KMSDecryptPolicy, StepFunctionsExecutionPolicy, EventBridgePutEventsPolicy.
  • Syntax: - DynamoDBCrudPolicy: { TableName: !Ref Table }. A template with no placeholders still needs an empty object: - CloudWatchPutMetricPolicy: {}.
  • Connectors (AWS::Serverless::Connector, or the Connectors attribute on the source resource) create least-privilege policies between a source and a destination. Permissions are Read (get data from the destination) and Write (send data or events to the destination, or change its data). You name the two resources and the access type, and SAM composes the IAM policy.
  • Choose a policy template when you know the template name for the access you need. Choose a connector when you want to state only "this function reads from or writes to that resource".

Remember

  • sam init creates a project from a template and creates samconfig.toml.

  • sam build builds functions and layers into .aws-sam/build.

SAM gradual deployments

Remember

  • AutoPublishAlias: live publishes a new version when the code changes and points the alias live to it.
  • Callers must use the alias, because the traffic shift happens on the alias.
  • A caller that uses the function name with no alias calls $LATEST and skips the gradual deployment.
  • DeploymentPreference makes SAM create the CodeDeploy application, deployment group, and role.
  • CodeDeploy changes the alias weights in steps to move traffic from the old version to the new version.
  • Canary types: Canary10Percent5Minutes, Canary10Percent10Minutes, Canary10Percent15Minutes, Canary10Percent30Minutes.
  • Linear types: Linear10PercentEvery1Minute, Linear10PercentEvery2Minutes, Linear10PercentEvery3Minutes, Linear10PercentEvery10Minutes.
  • AllAtOnce moves all traffic in one step.
  • A canary deployment has two steps. Example: 10% for 5 minutes, then the remaining 90%.
  • A linear deployment has equal steps with equal time between them.
  • Linear10PercentEvery1Minute adds 10% each minute, so all traffic moves in 10 steps.
  • An alarm in Alarms that enters ALARM state makes CodeDeploy send all traffic back to the old version.
  • A PreTraffic hook runs before traffic shifts. A PostTraffic hook runs after all traffic shifts.
  • Both hooks are optional. A hook that reports failure makes CodeDeploy roll back.
  • A hook function must call PutLifecycleEventHookExecutionStatus with Succeeded or Failed.
  • A hook function role needs permission for PutLifecycleEventHookExecutionStatus.
  • A hook with no status report makes the deployment fail after 1 hour.
  • For a new function, deploy first with AutoPublishAlias, then add DeploymentPreference.

Exam signals

  • "10% for 5 minutes, then all, roll back on errors, least effort" → Canary10Percent5Minutes with Alarms.
  • "Run a smoke test before any user traffic reaches the new version" → PreTraffic hook.
  • "Hook ran, but the deployment waits and then fails" → the hook did not call PutLifecycleEventHookExecutionStatus. CodeDeploy waits for that call, not for the function to return, and fails the deployment after 1 hour.

Explanation

Key facts

  • AutoPublishAlias: live publishes a new version when the code changes and points the alias live to it. Callers must use the alias, because the traffic shift happens on the alias. A caller that uses the function name with no alias calls $LATEST and skips the gradual deployment.
  • DeploymentPreference makes SAM create the CodeDeploy application, the deployment group, and the CodeDeploy role for you. CodeDeploy then changes the alias weights in steps, so that traffic moves from the old version to the new version.
  • Types: Canary10Percent5Minutes, Canary10Percent10Minutes, Canary10Percent15Minutes, Canary10Percent30Minutes, Linear10PercentEvery1Minute, Linear10PercentEvery2Minutes, Linear10PercentEvery3Minutes, Linear10PercentEvery10Minutes, AllAtOnce.
  • Canary: two steps. Canary10Percent5Minutes sends 10% of traffic to the new version, waits 5 minutes, then sends the remaining 90%.
  • Linear: equal steps with equal time between them. Linear10PercentEvery1Minute adds 10% each minute, so all traffic moves in 10 steps.
  • AllAtOnce moves all traffic in one step.
  • Alarms: CloudWatch alarms. If one alarm enters the ALARM state, CodeDeploy rolls back the deployment: all traffic goes back to the old version.
  • Hooks: Lambda functions that test the new version. PreTraffic runs before traffic shifts. PostTraffic runs after all traffic shifts.
  • Both hooks are optional. If a hook reports failure, CodeDeploy rolls back.
  • A hook function must report its result to CodeDeploy with PutLifecycleEventHookExecutionStatus (Succeeded or Failed). Its role needs permission for that call.
  • CodeDeploy needs an earlier version to shift traffic from. For a new function, deploy first with AutoPublishAlias, then add DeploymentPreference.

References: SAM gradual deployments, PutLifecycleEventHookExecutionStatus, Lambda versions (unqualified calls use $LATEST), AppSpec hooks (1-hour limit for a Lambda hook). Related set: Module 1 (Lambda versions and aliases).

AWS CDK concepts

Remember

  • A CDK app contains stacks, and a CDK stack contains constructs.
  • A construct is a class that represents one or more AWS resources.
  • Each CDK stack becomes one CloudFormation stack.
  • The CDK turns code (TypeScript, JavaScript, Python, Java, C#, Go) into CloudFormation templates.
  • An L1 construct is one CloudFormation resource with no defaults. Its name starts with Cfn.
  • An L2 construct is one resource with safe defaults and helper methods. Example: s3.Bucket.
  • An L3 construct (pattern) creates many resources for one common architecture.
  • Use L2 by default. Use L1 when no L2 exists or L2 does not support a property.
  • Use an L3 pattern when it matches your architecture and you want the least code.
  • cdk bootstrap deploys the CDKToolkit stack: an S3 asset bucket, an ECR repository, and IAM roles.
  • Run cdk bootstrap one time for each account and Region (environment).
  • Without bootstrap, only stacks with no assets and a template under 51,200 bytes deploy.
  • cdk synth makes the cloud assembly in cdk.out: the templates and the assets.
  • cdk diff shows the resources and permissions that a deploy will change.
  • cdk deploy deploys through a CloudFormation change set by default.
  • cdk deploy --hotswap updates resources through service APIs. Use it in development only, because it causes drift.
  • cdk watch deploys when files change and uses hotswap by default.
  • A grant adds a least-privilege IAM policy to the function role without policy JSON.
  • The current grant form is table.grants.readData(fn). Older study material shows table.grantReadData(fn), which still works but is discouraged.
  • RemovalPolicy maps to the CloudFormation DeletionPolicy.
  • The CDK default RemovalPolicy for S3 buckets and DynamoDB tables is RETAIN, the opposite of CloudFormation.
  • After cdk destroy, a retained bucket or table still exists and still costs money.
  • A retained resource makes a new deploy with the same resource names fail with a name conflict.
  • To delete a bucket with objects on cdk destroy, set removalPolicy: DESTROY and autoDeleteObjects: true.
  • removalPolicy: DESTROY alone cannot delete a bucket that contains objects.

  • "cdk destroy finished, but the bucket and table still exist" → default RemovalPolicy.RETAIN.
  • "Give a function read access to a table with the least code" → a grant method. One line adds a read-only policy for that one table to the function role.

Remember

  • Add an environment parameter, for example EnvType with AllowedValues: [dev, prod].
  • Mappings keyed by environment or Region give values such as instance size.
  • Mappings keys and values are literals. You cannot use parameters or functions inside Mappings.

  • Conditions can use parameters, pseudo parameters, mappings, and other conditions.
  • Conditions cannot use resources or resource attributes, because CloudFormation evaluates conditions before it changes any resource.

  • CodePipeline CHANGE_SET_EXECUTE runs the change set.
  • CodePipeline CREATE_UPDATE creates or updates the stack at once, with no review step.
  • CodePipeline REPLACE_ON_FAILURE deletes and recreates a failed stack. Use it for testing only.

  • Add an environment parameter (for example EnvType with AllowedValues: [dev, prod]).
  • Mappings keyed by environment or Region give values such as instance size. Mapping keys and values are literals. You cannot use parameters or functions inside Mappings.
  • Conditions use Fn::Equals on parameters. Attach Condition to a resource or output. Use Fn::If for property values.
  • Conditions can use parameters, pseudo parameters, mappings, and other conditions. They cannot use resources or resource attributes. CloudFormation evaluates conditions when it starts a create or update, before it changes any resource, so a resource value is not available to a condition.

Exam signals

  • "Template points to a local folder, create-stack fails" → aws cloudformation package, then deploy the output template. The package step uploads the folder and replaces the local path with the S3 location.
  • "Template body is too large" → upload the template to S3. A template in S3 can be up to 1 MB.
  • "Five functions share a helper library" → a layer, and one folder for each function.

Explanation

Packaging

  • aws cloudformation package --s3-bucket ... (or the same job with sam package) uploads local paths (for example CodeUri, Lambda Code, nested stack TemplateURL) to S3. A folder becomes a .zip file.
  • The package command writes a new template with the S3 locations. You need this step because CloudFormation runs in AWS and cannot read files on your computer.
  • aws cloudformation deploy creates a change set and runs it. With --no-execute-changeset, it stops after it creates the change set. Use it when someone must review the change set before it runs.
  • A template larger than 51,200 bytes must come from S3, because that is the maximum template body in a request. Use deploy --s3-bucket, which uploads the template to the bucket first.
  • sam deploy does the upload for you. resolve_s3 = true makes SAM create a managed bucket, so you do not create one.
  • Container image functions: PackageType: Image. The image is in Amazon Elastic Container Registry (ECR) (ImageUri). sam build builds the image from the Dockerfile in the function Metadata.

Project layout

  • template.yaml and samconfig.toml at the project root.
  • One folder for each function (its CodeUri), with its own dependency file (requirements.txt, package.json). Each package then contains only the code and libraries of its own function, so it stays small.
  • Shared code goes in a layer (AWS::Serverless::LayerVersion with ContentUri). Functions list it in Layers.
  • A layer is a .zip archive of shared code or libraries. Lambda extracts it into the /opt folder of each function that uses it, so you update the shared code in one place.
  • Test events go in an events/ folder. Tests go in a tests/ folder.
  • Do not edit files in .aws-sam/build. sam build overwrites them.
